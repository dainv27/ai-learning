## Architect
- Decision: Build a zero-dependency Node.js 22 ES-module Lambda in lambda/, deployed with AWS SAM behind an API Gateway HTTP API (payload v2). Define a single function `UptimeFunction` whose HttpApi event is declared as `Method: ANY, Path: /uptime`, not `GET /uptime`. HTTP API answers an unmatched method with its own 404 and never invokes the function, so the 405 and Allow header can only come from the handler if all methods reach it. The handler stays thin. It reads requestContext.http.method and rawPath. For GET on /uptime it returns 200 with a JSON string body {"uptimeSeconds": n}. For any other method it returns 405 with `Allow: GET`, a JSON error body in the shape { error: { code, message } }, and Content-Type. Unknown paths that reach the function return 404. Container start time is captured once at module scope when the module is initialized, using a monotonic clock (process.uptime() or performance.now() captured at load). Do not use a per-invocation Date.now() baseline, and never reset the start time inside the handler. A pure function `computeUptimeSeconds(startMs, nowMs)` is split out for unit tests and returns a non-negative number. Responses set `Content-Type: application/json; charset=utf-8` and `Cache-Control: no-store`. Tests use node:test against the exported handler with realistic v2 events (GET 200, POST/PUT/DELETE/PATCH 405 with Allow, wrong path 404). They also cover the warm-invocation case: two calls in the same module instance return non-decreasing uptime, with the clock injectable or the time faked. SAM template.yaml sets explicit Runtime nodejs22.x, Timeout and MemorySize, uses no extra IAM policies beyond the default basic execution role, and has an Output with the HTTP API endpoint URL.
- Components: lambda/template.yaml (SAM: UptimeFunction, HttpApi event Method ANY Path /uptime, Outputs with endpoint URL), lambda/src/handler.js (exported `handler`; method/path check; builds { statusCode, headers, body }), lambda/src/uptime.js (module-scope container start capture; pure `computeUptimeSeconds`), lambda/package.json ("type": "module", `node --test` script, no runtime dependencies), lambda/test/handler.test.js (node:test: 200, 405 + Allow, 404, Cache-Control, content type), lambda/test/uptime.test.js (node:test: pure uptime computation and warm-invocation monotonicity)
