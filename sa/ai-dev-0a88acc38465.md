## Requirement

Implement booking cancellation: a backend endpoint that cancels a booking, and a frontend page where a user can trigger the cancellation.

## Decision

Expose DELETE /api/v1/bookings/{bookingId} REST endpoint via BookingController that delegates to BookingCancellationService in application layer. Service orchestrates validation through BookingRepository, executes cancellation via domain BookingAggregate state transition to CANCELLED status, persists via repository, and publishes BookingCancelledEvent. Frontend implements BookingCancellationPage with confirmation dialog that invokes the endpoint via BookingApiClient. Database schema adds cancelled_at timestamp column to bookings table via Liquibase changeset. OpenAPI spec defines the endpoint contract first before implementation.

## Constraints

- Booking can only transition to CANCELLED from CONFIRMED or PENDING status, must reject if already CANCELLED or COMPLETED
- Must retain cancelled_at timestamp for audit trail and cannot physically delete booking records
- Endpoint must return 404 if booking does not exist, 409 if cancellation is not allowed for current status
- OpenAPI specification must be written and validated before any controller implementation begins
- Liquibase changeset must be idempotent and backwards compatible with zero-downtime deployment
- BookingCancelledEvent publication must occur within same transaction as status update to maintain consistency
- Frontend must require explicit user confirmation before calling DELETE endpoint to prevent accidental cancellations
- No direct database access from application or domain layers, all persistence through repository port
