## Requirement

Implement booking cancellation: a backend endpoint that cancels a booking, and a frontend page where a user can trigger the cancellation.

## Decision

Expose a DELETE /api/v1/bookings/{bookingId} endpoint via BookingController that delegates to BookingCancellationUseCase in the domain layer, which marks the booking as CANCELLED in the database via BookingRepository, enforces business rules (no cancellation after start time, refund calculation), and publishes a BookingCancelledEvent to the event bus. Frontend implements a BookingCancellationPage with a confirmation dialog that calls the cancellation endpoint and displays success/error feedback.

## Constraints

- Must prevent cancellation if booking start time has passed
- Must preserve audit trail by storing cancellation timestamp and reason in bookings table via Liquibase changeset
- DELETE endpoint must be idempotent - repeated calls with same bookingId return 200 if already cancelled
- Must validate user authorization - only booking owner or admin can cancel
- Must implement optimistic locking on Booking entity to prevent race conditions during status update
- OpenAPI specification must define DELETE /api/v1/bookings/{bookingId} with 200, 403, 404, 409 responses before implementation
- Frontend must handle network errors and 409 conflict responses gracefully with user-friendly messages
- Must not physically delete booking record - only status transition to CANCELLED state
