## Requirement

Viết một lambda function REST API trả ra danh sách các tỉnh của Việt Nam

## Decision

Generate an OpenAPI-first specification defining GET /v1/provinces and implement it within the payment module using hexagonal architecture. A Lambda handler receives API Gateway HTTP requests, delegates to ProvinceService, which initializes an in-memory lookup table from a Liquibase-seeded dataset during cold start. An outbound repository port abstracts the persistence layer, while inbound adapters serialize/deserialize against the generated OpenAPI types. All logic stays confined to core interfaces, with zero external network calls and deterministic payload shapes.

## Constraints

- Request/response payloads must strictly match the OpenAPI contract types; any schema drift breaks consumers and fails generated code
- Per-invocation database hits are forbidden due to Lambda cold-start latency; provinces must be materialized into an immutable structure once per container lifetime
- Core domain modules may not import AWS SDK, Spring, or relational drivers; only Java interfaces define the hexagonal ports
- Liquibase seed changelog must use MERGE/INSERT IF NOT EXISTS guarantees to prevent constraint violations on repeated executions
- Integration tests must auto-apply Liquibase to an ephemeral test database before each test suite run
- All DTO fields must be non-null and consistently ordered to prevent Jackson/DataBound serialization variance across environments
- The endpoint must return HTTP 200 with an empty array [] when no provinces exist, never HTTP 204 or internal error codes
