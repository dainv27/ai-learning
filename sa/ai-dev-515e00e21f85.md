# Architecture Design — Chúng mày tạo cho tao 1 API, mục đích triển khai trên Cloudflare Worker để để làm proxy vào các dịch vụ nội bộ

- Workflow: `ai-dev-515e00e21f85`
- Repository (logical): `cloudflare`
- Module: `proxy`

## Requirement

Chúng mày tạo cho tao 1 API, mục đích triển khai trên Cloudflare Worker để để làm proxy vào các dịch vụ nội bộ

## Decision

Build a Cloudflare Worker in TypeScript with ES modules (export default { fetch }), deployed with Wrangler (wrangler.toml). It acts as an allowlist-based reverse proxy and is not a generic forwarder. The route format is /<service-key>/<path...>. The Worker looks up <service-key> in a static, code-defined registry (SERVICE_REGISTRY) that maps it to an internal origin URL taken from env bindings, plus the allowed methods, an allowed path-prefix list, and a timeout. Anything outside the registry gets 404, and a disallowed method gets 405 with an Allow header. The client never supplies the upstream host or URL. Internal origins are reached over HTTPS. Where possible, service bindings or Cloudflare Tunnel are used, and the upstream hostname is read only from env vars, never from request data.

Request flow in the fetch handler: (1) normalize and validate the path (reject '..', encoded traversal, '//', control characters, and over-long URLs); (2) authenticate the caller at the edge before any forwarding, using a shared-secret or service token compared in constant time (PROXY_CLIENT_TOKEN as a Wrangler secret), with Cloudflare Access JWT validation as an alternative if configured, and return 401 or 403 on failure; (3) resolve the service and path against the registry; (4) build the upstream Request by copying the headers through an allowlist, stripping hop-by-hop headers (Connection, Keep-Alive, Transfer-Encoding, TE, Upgrade, Proxy-*), the client Cookie and Authorization, and any client-supplied Host or X-Forwarded-* values, then injecting the per-service upstream credential from env secrets plus an X-Request-Id; (5) call fetch with an AbortController timeout and redirect: 'manual'; (6) stream the upstream body back, filtering response headers (drop Set-Cookie and internal-only headers such as Server and X-Powered-By) and setting an explicit Cache-Control (no-store by default). Errors use the shared shape { error: { code, message } } with 400, 401, 403, 404, 405, 413, 502 and 504. The messages never expose the upstream URL, secrets or stack traces. Each request is logged as structured JSON with the request id, service key, status and latency, and the log never contains header values or bodies. A GET /healthz endpoint is served locally and does not call any upstream.

The AWS Lambda/SAM standard is adapted, not copied: the thin-handler idea, explicit status codes, a consistent error shape, 405 with Allow and edge validation are kept. The Lambda event shape, SAM, nodejs22.x and IAM are dropped. Tests use Vitest with @cloudflare/vitest-pool-workers, or Miniflare, with the upstream fetch mocked.

- proxy/src/index.ts (Worker entry: export default { fetch }, thin router and top-level error boundary)
- proxy/src/config/serviceRegistry.ts (SERVICE_REGISTRY: service key → env binding name, allowed methods, allowed path prefixes, timeout, max body size)
- proxy/src/auth/authenticate.ts (edge caller authentication with constant-time token comparison)
- proxy/src/routing/resolveTarget.ts (path normalization, traversal rejection, allowlist match, upstream URL construction)
- proxy/src/http/headers.ts (request and response header allowlists, hop-by-hop stripping, upstream credential injection)
- proxy/src/http/forward.ts (upstream fetch with AbortController timeout, redirect:'manual', streamed response, 502/504 mapping)
- proxy/src/http/errors.ts (error shape { error: { code, message } } and status mapping)
- proxy/src/types/env.ts (Env interface: service origin vars and secret bindings)
- proxy/wrangler.toml (name, main, compatibility_date, vars for origins, service bindings, no secrets in file)
- proxy/test/*.test.ts (Vitest Workers pool: allowlist, auth, header stripping, timeout, method and path rejection, error mapping)
- proxy/package.json and proxy/tsconfig.json (wrangler, typescript, vitest, @cloudflare/workers-types)
- proxy/README.md (route format, how to register a service, how to set secrets via wrangler secret put)

## Constraints

- Allowlist only: the upstream origin is determined solely by SERVICE_REGISTRY and env bindings. No client-supplied host, URL, scheme or port may influence the target. Any unknown service key or path prefix returns 404, and the Worker must never act as an open proxy or SSRF vector.
- The registry's real internal hostnames and credentials are not specified in the requirement, so the code must use placeholder env bindings (e.g. SERVICE_<NAME>_ORIGIN) with clearly marked example entries. No real internal hostnames, IPs or secrets may be committed in the code, wrangler.toml, tests or README.
- Callers must be authenticated before any upstream call. The token is held as a Wrangler secret, compared in constant time, and never logged. A missing or invalid token returns 401 or 403 with no upstream traffic.
- Do not forward client Cookie, Authorization, Host, hop-by-hop headers or client X-Forwarded-* values. Upstream credentials are injected only from env secrets. Strip Set-Cookie and internal headers from responses. Secrets, upstream URLs and stack traces must never appear in a response body, header or log.
- Path normalization must reject '..', encoded dot-segments (%2e%2e), backslashes, '//' and control characters before matching the allowlist. Query strings are forwarded unchanged only for allowlisted paths.
- Every upstream call has an explicit timeout (default 10s, configurable per service) via AbortController, uses redirect:'manual' (upstream redirects are not followed), and maps failures to 502 (connection error) or 504 (timeout). Bodies are streamed, not buffered. Requests over the configured size cap are rejected with 413 via Content-Length and a streaming limit, staying within Worker subrequest, CPU and body-size limits.
- Methods are restricted per service. A disallowed method returns 405 with an Allow header. Error responses always use { error: { code, message } } with a deliberate Cache-Control (default no-store).
- Runtime is the Workers runtime only: no Node-only APIs (fs, net, Buffer-dependent code), and no AWS artefacts (no SAM template, Lambda handler or API Gateway event parsing). Use Web-standard Request, Response, Headers and URL. Pin compatibility_date in wrangler.toml.
- Tests must run offline with the upstream fetch mocked, and must cover 200 passthrough, 400, 401/403, 404, 405 with Allow, 413, 502, 504, header stripping and path traversal rejection. Only files under proxy/ may be created or modified, to minimise merge conflicts and avoid regressions in other modules of the cloudflare repo.
