# Architecture Design — Viết một lambda function REST API trả ra danh sách các tỉnh của Việt Nam

## Requirement

Viết một lambda function REST API trả ra danh sách các tỉnh của Việt Nam

## Decision

Implement a read-only REST endpoint GET /v1/provinces in the payment module using OpenAPI-first contract, hexagonal application layer with a query service, and a JPA repository backed by a Liquibase-seeded table of Vietnam's 63 provinces.

## Components

- ProvincesApi (OpenAPI generated interface)
- ProvincesApiController (REST adapter)
- ProvinceQueryService (application service)
- ProvinceRepositoryPort (port interface)
- JpaProvinceRepository (persistence adapter)
- ProvinceJpaEntity (JPA entity)
- ProvinceResponseDto (DTO)
- liquibase-change-log.xml (changeset for provinces table and seed data)

## Constraints

- The endpoint contract must be defined in OpenAPI YAML and generated code used; no hand-written @RequestMapping annotations.
- Only the payment module of booking-service may be modified; no changes to other modules or shared libraries.
- The provinces data must be read-only — no POST/PUT/PATCH/DELETE endpoints, and no service methods that mutate state.
- Liquibase must be used to create the provinces table and seed all 63 official Vietnamese provinces/cities; any missing or incorrect seed row is a release blocker.
- The response DTO must contain only province code and name; internal entity fields or JPA annotations must not be exposed.
- Integration tests must verify the endpoint returns the exact Liquibase-seeded rows and that the response is valid JSON per the OpenAPI schema.
- The endpoint path must be exactly /v1/provinces and the API version prefix must not be changed without a separate specification decision.
- No external calls or data access beyond the booking-service database are permitted for this endpoint.
