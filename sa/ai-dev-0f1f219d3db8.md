## Requirement

Implement booking cancellation: a backend endpoint that cancels a booking, and a frontend page where a user can trigger the cancellation.

## Decision

REST endpoint POST /api/v1/bookings/{bookingId}/cancel with idempotent cancellation handling. Hexagonal architecture with domain service coordinating state transition, outbound port for persistence, and application service exposing the use case. Frontend SPA page fetches booking details via GET /api/v1/bookings/{bookingId}, displays cancellation confirmation dialog, invokes cancel endpoint, and shows success/error feedback. OpenAPI spec defines contract first, domain enforces booking state machine rules (only CONFIRMED bookings can be cancelled), cancelled bookings transition to CANCELLED state with timestamp.

## Constraints

- Only bookings in CONFIRMED state can be cancelled per domain rules
- Cancellation must be idempotent: calling cancel on already CANCELLED booking returns success without error
- Database schema must support CANCELLED as valid booking state enum value via Liquibase migration
- OpenAPI contract must be defined before implementation and validated in CI
- No direct database access from application layer: all persistence through BookingRepository port
- cancelled_at timestamp must be recorded in UTC for audit trail
- Booking state transitions must maintain referential integrity with related entities (no orphaned records)
- Frontend must handle 404 (booking not found), 409 (invalid state transition), and 401/403 (unauthorized) error responses
